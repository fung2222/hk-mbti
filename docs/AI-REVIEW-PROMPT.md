# AI 評測提示詞（Roy 拎去問唔同 AI 用）

> **用法**：整段複製去任何 AI（Gemini／ChatGPT／Claude／Grok／DeepSeek／Qwen…），
> 收到報告之後**原封不動傳返畀 Apps 主管**做覆核（流程見 `docs/AI-REVIEWS-LOG.md`）。
> **設計目的**：迫 AI 交證據、講明自己有冇真睇過 → 過濾「憑估嘅報告」（今日三份有兩份就係憑估）。

---

## 完整版（推薦）

```
你係資深前端 + 產品審計員。任務：對「港式 MBTI」網頁 app 做可覆核嘅審計，唔係寫感想。

網址：https://fung2222.github.io/hk-mbti/
（Android 版係 TWA 殼載呢個網站；網站原始碼公開喺 GitHub Pages）

=== A. 先講你嘅方法（必答，唔准含糊）===
1. 你有冇真係打開／爬過個網頁？定係憑推測？（有地區限制／讀唔到就照實講）
2. 你實際檢查咗邊幾頁、量咗咩、用咩方法？
（講明「推測」比假裝做過有用。）

=== B. 已知事實（請逐項核實；錯就指出）===
- 109 條自編廣東話題目、5 條軸（E/I、S/N、T/F、J/P、T/A 情緒軸）
- 3 個版本：60 / 30 / 10 題
- 純前端（GitHub Pages）、零後端、免註冊、答案只存本機 localStorage
- 離線可用（Service Worker 預cache 核心資源）；語音朗讀用預錄 mp3（767 條）
- 分享卡 720×1280（9:16）；16 型百科（每型 9 章，第 1 章免費）＋136 組配對＋性格比較工具
- 追蹤只有 GoatCounter（無 cookie、唔記 IP）；另有香港 16 型分佈對照頁（INFP 最多，約 11%）

=== C. 已知設計決定（唔好花篇幅建議改呢啲，除非你有材料證明係錯）===
- 全站冇 emoji；字重只用 400/600/700/900（禁用 500/800）
- 16 型卡＝直角、9/16 比例、4px 密格；唔用插畫公仔
- 唔加帳號、唔加第三方追蹤（GA 等）、唔加後端
- 首頁刻意留白、少卡框（app 感，唔係功課紙）

=== D. 要查嘅六件事（每項要：發現 + 證據 + 嚴重程度 + 建議改法）===
1. 內容一致性：頁面文案／數字同實際程式數據有冇唔一致？（自稱題數、百分比、字數、長度上限）
2. 計分邏輯邊界：打和、全部選同一邊、接近 50% 嘅情況，行為合唔合理？有咩漏洞？
3. 弱網／離線：斷網、慢網、答到一半關 app 再開，邊一步會爆？
4. 傳播設計：分享卡同結果頁，點解有人會／唔會 post？具體缺咩？（唔要「加插畫」呢類空話）
5. 競爭對照：同 16Personalities／Truity 等嘅免費層比，本 app 多咩／缺咩？（要列實際功能對比）
6. 你自己揀一個你認為最有價值嘅角度深入寫（例如無障礙、ASO、留存、效能、文案感染力）。

=== E-1. 未測風險清單（必答，唔准因為「未測到」就略過）===
就算你冇能力實測，都要列出你認為**最可能出事嘅 5 個情境**，每個寫明：
情境（點樣重現）｜你估會出咩事｜為咩你覺得風險高。
（實例：2026-10-13 一次真機驗收捉到「飛行模式下下拉更新 → 出空白彈窗、撳唔到」，
源頭正是「Service Worker 更新後新舊版本唔兼容」＋「清除快取但保留網站資料」呢兩個情境。
問對問題，往往比評分有價值。）

=== E. 輸出格式（跟住寫，唔好寫散文）===
【方法】做過咩 / 邊啲係推測
【核實 B 段】逐項：對 / 錯（附證據）
【發現】1. 標題｜證據｜嚴重程度（阻上架 / 影響用戶 / 美觀）｜建議
        2. …
【最想我改嘅 3 樣】排序 + 理由
【評分（可選）】每一分要對應上面邊個發現

=== F. 規矩 ===
- 唔准編造檔案路徑、URL、數字；唔確定就標「未證實」
- 唔好重複「加載入動畫／加圖卡／加插畫」呢類通用建議（除非有實測證明而家壞）
- 直接講錯處，唔需要客氣
```

## 之後點做
1. 收到 AI 報告 → **原文傳返畀 Apps 主管**（唔使整理）。
2. 主管照 `docs/AI-REVIEWS-LOG.md` 六步流程處理：逐項實測 → 分「可採納／要你拍板／唔跟」→ 值得做嘅修＋加守門＋出貨。
3. 如果份報告冇新嘢，主管會直接同你講「可以唔理」。
