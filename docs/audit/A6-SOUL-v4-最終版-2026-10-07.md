## 一、開工前（唔可以跳）
1. 睇現況先講嘢：`git log --oneline -5`、`git status`、**讀今次要改嗰個檔同父層嘅原文**。唔准靠記憶。
2. **只讀今次相關嗰段** skill／reference（改 CSS 讀美學＋typography；改題目讀題庫嗰份）。**唔准讀晒 82 份**（44 萬字）。出貨規則已經寫入 `tools/ship.sh`，唔使每次讀 push-helper。

## 二、改之前（防「一擊不中」）
改 CSS／class／版面前，**grep 三樣**：
1. **父層有冇 `space-y-*`／`gap`／`margin` 會蓋走目標**（血例：`mb-4` 被 `space-y-3` 寫成 0）。有就寫 **id 級 selector**，唔好加一個會被蓋嘅 class。
2. **同名 `function`／`window.X =`／同名 class 出現 ≥2 次** → 後面靜靜蓋前面。先查邊度仲有用。
3. **禁令**：`font-weight:800`、`font-weight:500`、任何 emoji。

改大檔**嚴禁按字元 slice**（`index.html` 約 7,100 行，inline script 約 17 萬字）。用**函數名做錨**；搬完對 `function`／`window.X =` 名單，前後唔同就 `git checkout -- 該檔`，**唔好補洞**。一個 turn 一項，一個 commit revert 得返。

## 三、改之後（即時，唔使等閘）
1. `python3 tools/preflight.py`（約 0.9 秒）—— 捉 inline script 語法同禁字。紅就停。
2. 真 Chrome（Playwright，`file://`）用 `getComputedStyle` 量**生效值**（margin／底色／對比）。**值冇變 = 未算改到**；唔好只查 class 在唔在。
3. **截圖 390、日光同黑夜（`html.dk`）→ `vision_analyze` 自己睇。呢步唔可以省。** 數字睇唔出嘅 bug（例：底色同背景只差 0.0003、金標對比 2.11）只有眼睇得到。
4. **數字同眼見打架 → 信眼見**，再補一條量「人見到嘅屬性」嘅斷言。

## 四、守門（先見紅，再見綠）
先寫一條**會 fail** 嘅斷言（要量**生效值**，唔好只驗 class 在唔在），**親眼見佢 fail**，先改，同一條 pass 先算修好。斷言**同修復同一個 commit**。清單／數值由資料動態計，唔准寫死會變嘅值；加元素漏更新，測試要即刻紅。

## 五、出貨
- **只准 `sh tools/ship.sh "msg"`**（唯一准 push 嘅途徑）。唔准自己 `git push`。閘寫入程式碼：唔全綠就拒絕。
- **只信每個閘自己嘅 exit code**；「冇輸出」「冇紅字」唔等於過。
- 11 套閘**兩批並行**（約 107 秒，數字由腳本自己數）；快閘（語法壞）**約 6.7 秒**就拒絕，唔跑慢閘。**紅過之後，push 前必須再全綠一次**。綠跑永遠 11 套齊。
- 會先列出將入 commit 嘅檔（`git status --short`）；有唔相關檔就停。
- ship 完自動對 live `index.html` md5（Pages 有時 5–10 分鐘先上）。**未對上就照實講「未對上」，唔好講已更新。**
- **一輪工作只 push 一次**（Pages build queue 會塞）。
